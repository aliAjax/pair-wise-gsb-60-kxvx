# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览，含外部报告号入账数与结论失效/重算提示
- `/signals`：关键词与多条件筛选、人工登记新信号、结论生效状态
- `/imports`：离线报告包导入与断点续作（幂等归并、故障演练、重算队列）
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本（失效/重算/生效）、重新打开和审计
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖、唯一外部报告号与高风险关联
- `/audit`：跨信号审计时间线、外部报告入账台账、导入批次、重算记录和 JSON 报告导出

## 离线报告包处置链

安全运营组每月在现场离线整理维修、投诉和现场报告，回内网后在 `/imports` 与信号台账合并：

- **同一外部报告号只入账一次**：全局入账台账 `externalLedger` 对 `externalReportId` 去重，
  包内重复导出与跨包重复引用均判为 duplicate，不增加报告数与证据。
- **新产品或新批号建立案例**；产品与批号均已存在时，按故障模式（`产品+批号+故障模式` 三元组）归并，
  证据、报告计数、暴露台数与发生率在同一事务内更新。
- **接收失败可从未完成处重试**：每条报告独立事务提交，失败前不产生任何写入，不会形成半套案例；
  批次停在第一条 pending/failed，刷新页面或点击重试均从断点继续。
- **新证据使旧结论失效重算**：证据变化事务内立即把生效版本置为 invalidated 并同步批次统计、总览与审计；
  重算结论保存成功后新版本才恢复 active，失败回退失效态并可手动重试。旧版本永久保留并标记取代关系。
- **旧浏览器数据升级**：v1（`medical-safety-signals-v1`）首次加载时迁移为 v2（`medical-safety-workbench-v2`），
  保留全部原审计与结论，回填故障模式与外部报告标识并补记入账台账，继续参与后续计算。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建与检查

```bash
npm run check
npm run build
node scripts/verify-chain.mjs   # 处置链端到端逻辑验证（49 项断言）
```

无后端服务，页面使用确定性模拟数据，并将工作台状态（信号、证据、版本、审计、入账台账、导入批次、重算任务）
持久化到浏览器 `localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。
`/imports` 提供故障注入按钮，可分别模拟“下一条报告接收失败”和“下一次结论重算保存失败”，
用于验证断点续传与结论安全恢复。
