# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、待重算结论、报告包接收状态、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号
- `/imports`：离线报告包接收（JSON 上传/粘贴/示例包）、故障演练、断点续作与批次事件追踪
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本（失效/自动重算）、重新打开和审计
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖、入账报告数、重算发生率与待重算案例
- `/audit`：案例审计 + 报告包接收事件的统一时间线和 JSON 报告导出

## 离线报告包处置链

安全运营组每月把维修、投诉、不良事件和现场报告整理成离线报告包，回内网后在 `/imports` 合并：

1. **幂等入账**：每条外部报告以 `externalReportId` 唯一标识；同一报告号在包内重复或跨报告包重复导入都只入账一次（升级前的浏览器旧证据使用稳定的 `LEGACY-` 标识继续参与去重）。
2. **建案与归并**：新产品/新批号/新故障模式建立新案例；产品 + 批号 + 归一化故障模式（见 `failure-mode.ts`）一致时归并到已有案例，累加报告数、暴露台数、批号并集和严重度。
3. **断点续作、无半套案例**：每条报告分两个原子持久化阶段——`receive`（幂等检查 + 入账 + 旧结论失效）和 `recompute`（重算并保存新结论）。接收阶段失败不写入任何内容；重算阶段失败则报告已入账、案例保持“结论待重算”。所有写入先在内存构造完整状态、校验后一次性提交（`persistDb`），失败即整体放弃。可在失败卡片上“从未完成处续作”，刷新页面后游标和原始报告仍保留在 localStorage。
4. **结论失效与重算**：新证据（外部报告或人工补录）使受影响案例当前 active 版本失效（`invalidated`，保留原因和时间），按确定性规则（证据强度、严重度、重算发生率）生成新的自动版本；**新版本保存成功后结论才恢复 `active`**。批次统计、总览指标和审计时间线由 store 派生同步更新。
5. **旧数据升级**：浏览器中的 v1 数据首次打开时自动迁移到 v2，原审计原样保留，仅追加一条“数据升级”审计；投诉/维修/不良事件/现场报告类旧证据补外部报告标识，v1 原始数据备份到 `medical-safety-signals-v1-backup`。

`/imports` 页提供三种故障演练（接收失败 / 重算保存失败 / 持久化失败），故障只触发一次，便于演示续作恢复。

## 测试

```bash
npm test          # Vitest：幂等、建案/归并、断点续作、失效重算、原子性、v1 迁移
```

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建与检查

```bash
npm run check
npm run build
```

无后端服务，页面使用确定性模拟数据，并将信号、证据、版本和审计记录持久化到浏览器 `localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。
